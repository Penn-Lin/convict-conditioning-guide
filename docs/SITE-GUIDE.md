# 囚徒健身 · 六艺十式动作指导站 —— 功能全览与使用指南

> 本文档面向两类读者：**想快速搞清这个站到底做了什么**的人，以及**每天真的要打开它练**的人。
> 第一部分讲「有什么」，第二部分讲「怎么用」，第三部分讲「你可能没注意到的细节」，第四部分讲「还没做的」。

线上地址：<https://convict-conditioning-guide.adasoigivea.workers.dev>

---

## 0. 一句话定位

把《囚徒健身》的 **6 门艺 × 10 式 = 60 式** 动作，整理成**结构化、可在手机上随时查**的指导页；
并在其上叠了一个**动态训练计划引擎** —— 每天按你的恢复状况、完成度、疲劳与负荷重叠算出「今天练什么、练多少」，训练完记录一次就闭环。

技术形态上有三件事要先说清楚，因为它们决定了这个站的性格：

| 特性 | 说明 |
|---|---|
| **纯静态单页应用** | 没有服务端、没有数据库、没有账号。构建产物是一堆静态文件，托管在 Cloudflare Workers 静态资源上。 |
| **数据 100% 存在你的浏览器里** | 训练记录、进度、打卡状态全在 `localStorage`。换个浏览器/清一次数据就没了（详见 §8）。 |
| **手机上用** | 375px 宽是主要目标；底部有固定标签栏，深色模式全套适配，触控目标一律 ≥44px。 |

```
*                        404 兜底（保留顶栏与页脚）
```

**导航有三套，不是重复，是分场景：**

- **顶栏**：桌面端铺开五项主导航；移动端收进汉堡菜单（可键盘操作）。
- **底部标签栏**（仅手机）：首页 / 六艺 / 训练 / 原则 —— 训练中在「动作页 ↔ 计划页」之间来回切只需一次点击。这是它存在的唯一理由。
- **页脚**：首页 / 六艺总览 / 训练原则 / 关于。

> 细节：顶栏**刻意不吸顶**。滚动时不会出现跟随动画或阴影变化，减少视觉噪音。
> 细节：`/plan` **不在 sitemap 里**。它是个人的当日计划页，没有检索价值。
> 细节：路由切换会瞬时回顶（`behavior: 'instant'`）；但页内 `#锚点` 跳转不受影响，该平滑还是平滑。

## 2. 内容体系：60 式

每门艺有 10 式，从第 1 式（入门）递进到第 10 式（高阶）。**每式固定 12 个字段**，全部结构化，不是一段散文：

| 字段 | 内容 |
|---|---|
| 中文名 / 英文名 | 如「标准俯卧撑 / Full Push-ups」，英文名可作检索与后续配图用 |
| 难度 | 入门 / 初级 / 中级 / 进阶 / 高阶 |
| 动作描述 | 一段话：这是什么动作、练什么 |
| 分解步骤 | 有序列表，4–7 步 |
| 要领要点 | 3–5 条 |
| 常见错误 | 3–5 条，写作格式固定为「错误表现 —— 纠正方法」 |
| 进阶标准原文 | 达到什么程度算过关 |
| 降阶方案 | 太难时退到哪一式 |
| 训练目标 | **三档**：初级 → 中级 → 升阶 |
| 主要发力肌群 | 标签列表 |
| 风险提示 | 仅高风险式填写（倒立撑全系、桥全系、单臂类） |
| 上一式 / 下一式 | 由程序按下标自动派生，数据文件里**不许手写**（防止人工编号错漏） |

**难度的定义方式值得注意**：它不是逐式单独评的，而是**按式号固定分段**——
1–2 式=入门，3–4 式=初级，5–6 式=中级，7–8 式=进阶，9–10 式=高阶。
所以同一门艺里，「第 5 式」在第几段是唯一的，不会出现主观漂移。

**60 式全部完成**后代表整个体系走完，首页与总览页会分别显示 `60/60`。

## 3. 页面逐个说

### 3.1 首页 —— 只回答两个问题

首页被刻意做「窄」了：**只回答「今天要做什么」和「我练到哪了」，不承担任何操作。**

| 板块 | 色调 | 内容 |
|---|---|---|
| ① 训练安排 | 橙（唯一重心） | 主训动作 + 辅助动作 + 预计总时长 + 一个实心按钮 |
| ② 本周概况 | 蓝 | 本周训练 `N/目标天数`、六艺总进度 `N/60`、累计记录次数 |
| ③ 六艺进度 | 中性 | 六行降噪列表：序号徽章 + 名称 + `N/10` + 当前式名 + 进度条 |
| ④ 建议关注 / 怎么开始 | 紫 | **随状态变化**：有记录 → 挑出「最久没练且没练完」的那门；零记录 → 三步上手引导 |
| ⑤ 安全提示 + 入口 | — | 训练原则、关于与免责 |

①有三个**互斥状态**：没设置过（显示「开始设置」）、今天还没练（显示计划摘要 + 「开始训练」）、今天已练完（显示完成态）。

> 设计取舍：v2 首页曾有「继续训练卡」和「今日计划条」两个同等重量的板块，而且两者口径不同（一个说「原书顺序第一个没练完的艺」，一个说引擎算出来的主训），用户不知道该信哪个。v3 删掉了前者，**只保留引擎的答案**。

### 3.2 六艺总览

六张进度卡（每张含：序号、中英文名、一句话定位、`N/10`、当前式名、状态标签），加一条**带状态的推荐练习顺序时间线**（✓ 已完成 / ● 进行中 / ○ 未开始 —— 形状区分，不只靠颜色）。

### 3.3 六艺详情

- 页头：`第 N 艺 / 共 6 艺` + 「当前：第 N 式 XXX」
- **本门进度环** + 主 CTA「继续第 N 式」（零进度时显示「从第 1 式开始」）
- 艺介绍 + 主要发力肌群
- **十式进阶路径**：一条竖向阶梯，标出你在哪一级
- 十式列表：每式一张卡，含难度徽章、描述摘要、进度状态
- 底部：上一艺 / 下一艺（第一艺与最后一艺显示为不可点状态）

### 3.4 十式详情（核心页）

按「训练中掏手机查一眼」的场景重排过：

1. 面包屑 + 标题（中文名大字 + 难度徽章 + 英文名）
2. **图位条**（紧凑条，不是大灰框，见 §5）
3. 动作描述（**四色自动高亮**，见 §5）
4. 风险提示（只在高风险式出现）
5. **进阶条件打卡卡** ← 前置到这里，因为它是你最需要操作的部分
6. 吸顶页内锚点：步骤 / 要领 / 错误 / 目标 / 降阶
7. 七个折叠板块：分解步骤、要领要点、常见错误、进阶标准原文、训练目标（常驻展开）、降阶方案、主要发力肌群
8. 安全提示 + 上一式 / 下一式
9. **吸底常驻进度条**：实时显示「进阶条件 3/5」，右侧按钮直接跳到打卡卡

**打卡的完整闭环：**

```
逐项勾选 → 勾满解锁主按钮 → 点「完成本式 · 进入第 N+1 式」
  → 进度 +1 → 显示「已进入第 N+1 式」→ 可一键撤销退回
```

两个「不让人卡死」的设计：

- **勾不满也能走**：勾满前按钮是灰的，但下方有一条「跳过条件，直接标记完成」的次要入口。现实中有人今天状态不好、只想先往下看，硬卡住只会让人放弃使用。
- **随时可撤销**：已完成状态显示「撤销，退回到第 N 式」。

> `currentStep` **只由你点击驱动，永不自动上升**。这是「不要每次训练都自动升级」在界面上的落点。

### 3.5 训练页（`/plan`）

整页分六块：

| 板块 | 色调 | 内容 |
|---|---|---|
| ① 今天练这些 | 橙 | 一句话摘要 + **时间账四格** + 训练项卡片列表 + 「开始训练」按钮 |
| ② 加练自选 | 中性描边 | 互补性好但今天没排进来的 1–2 项，**不自动加入** |
| ③ 为什么今天练这些 | 紫 | 可折叠的解释面板，每一条都由真实数值算出 |
| ④ 训练提示 | 紫 | 组间休息参考值、时间账、富余时间怎么办、疼痛提醒 |
| ⑤ 本周 | 蓝 | 进度环 + 本周训练天数 + 六艺总进度 |
| ⑥ 我的训练设置 | 中性 | 每周目标、默认时长、本地存储说明 |

两个抽屉（一天只用一次，所以收起来，不占主屏）：

- **「调整」**：训练安排方式（原书模板 / 自动调度）→ 时间档（15/30/45/60）→ **今天的训练量档**（初级/中级/升阶）→ 训练量微调（每项组数 −1 / ±0 / +1）→ 今天不想练哪门 → 换一个方案 / 重置全部调整
- **「开始训练 · 记录完成情况」**：见 §4

**时间账四格**是这一版新增的：热身 / 训练 / 放松 / 余量。以前的版本只报训练净耗时，导致「选 60 分钟只排出 8 分钟，剩下 52 分钟建议你去热身」这种荒谬结论。

### 3.6 训练安排方式（v4 新增）

「今天练哪几门」这件事有三套策略，在训练页的「调整」抽屉里切换（**长期设置**，改一次之后每天都按它排）：

| 方式 | 今天练哪几门 | 适合谁 |
|---|---|---|
| **渐入佳境**（原书，默认） | 六艺全练 | 大多数人。原书原话：「也许是最好的基础训练计划」 |
| **初试身手**（原书） | 只四艺（俯卧撑 / 深蹲 / 引体 / 举腿），**不含桥和倒立撑** | 完全新手。原书说这两门对关节要求更高 |
| **自动调度** | 引擎按恢复、疲劳、负荷重叠每天重算 | 生活不规律、时间不固定 |

**默认值由引导里的自评水平推导**（不新增问题）：完全新手 → 初试身手；练过一阵 / 有基础 → 渐入佳境。老存档升级时也会自动补上这个默认值。

**原书模板怎么决定「今天轮到哪几门」——不绑定星期几：**

```
今天到期的科目 = 距上次训练 ≥ 2 天的艺（从未练过的直接到期）
```

这条规则的推演：

| 情况 | 结果 |
|---|---|
| 隔天练（距上次 2 天） | 六门全部到期 → **六艺全练** |
| 中间空了两天（距上次 3 天） | 依然全部到期 → **六艺全练**，不补也不欠 |
| 一周出现第 4 次训练 | **正常**。隔天 = 7÷2 = 3.5 次/周，本就是「4 次周与 3 次周交替」 |
| 连着两天练（距上次 1 天） | 到期集合为空 → 兜底：**科目照排，但统一降到初级档（每门 1 组）** |

依据原书：「如果你觉得并无大碍还可以训练，那就练些低难度的动作（根据具体情况自行判断）」。

**训练量怎么定**：从「中级档（每门 2 组）」起逐档下试，取第一个装得进你时间档的档位 —— 装不下才退到初级档（每门 1 组）。「2 组」是原书的日常量（「我通常建议练习两组」）。

**实测时长（含热身 3 分钟 + 放松 2 分钟）：**

| 时间档 | 渐入佳境（六艺） | 初试身手（四艺） |
|---|---|---|
| 15 分 | 初级档 · 14.9 分 | 初级档 · 11.7 分 |
| 30 分 | 中级档 · 33.0 分 | 中级档 · 26.6 分 |
| 45 分 | 中级档 · 33.3 分 | 中级档 · 26.8 分 |
| 60 分 | 中级档 · 34.6 分 | 中级档 · 27.9 分 |

注意 45 / 60 分档和 30 分档给出的是**同样的量** —— 这不是算错了，原书「渐入佳境」的实际内容就这么多，多出来的时间是留给热身、放松和随时停顿的富余。

**模板模式与自动调度的边界（哪些变了、哪些没变）：**

| 环节 | 变了吗 |
|---|---|
| 今天练哪几门 | ✅ 变了（模板清单 vs 引擎计算） |
| 训练量档 / 组数 / 单组次数 / 组间休息 | ❌ 完全共用 |
| 时间账（热身 / 训练 / 放松 / 余量） | ❌ 完全共用 |
| 逐组记录、疲劳反馈、晋级判定 | ❌ 完全共用 |
| 加练自选池 | ✅ 模板模式下关闭（科目已排满） |
| 硬门控（今天练过 / 太累 / 停滞 → 排除某门） | ✅ 模板模式下**不排除**，改为「距上次满 2 天才排」+ 完成度崩过自动降档 |

## 4. 训练计划引擎

这是整站最重的部分。一句结论：**它不是随机推荐，是一套可解释的确定性规则。**

### 4.1 零随机

同一个状态 + 同一组选项，**永远产出同一个计划**。所以：

- 「换一个方案」= 把当前主训排除掉重算一遍，不是掷骰子；
- 同分时用原书顺序做 tie-break；
- 单测可以逐字断言每一个数字。

### 4.2 排几项

```
最终项数 = clamp(时间档上限 + 周缺口加成 − 疲劳抑制, 1, 5)
```

| 因子 | 规则 |
|---|---|
| 时间档上限 | 15 分→2 项，30 分→3 项，45 分→4 项，60 分→5 项 |
| 周缺口加成 | 本周剩余天数**已经补不上**训练次数缺口 → +1 项（周一缺口大但时间充裕，不动；周六才触发） |
| 疲劳抑制 | 六艺疲劳现值均值 ≥ 4.0 → −1 项 |
| 硬上限 | 无论怎么叠加，最多 **5 项** |

> 统计口径：同一天练两门艺只算 **1 次**训练（按日期去重），不刷分。

### 4.3 每项做多少（训练量档）

引擎先决定**今天用第几档**，再取该式的阶梯得到「几组 × 几次」。
前两级在两种模式下相同，第三级不同：

| 优先级 | 规则 | 为什么 |
|---|---|---|
| 1 | **软降量**：上次完成度 < 60% → 在长期档位基础上再降一档，且**忽略时间档下限** | 练不动的时候，时间多不代表该加量 |
| 2 | **你手动指定的档位**（`volumeTierOverride`） | 「我今天想练哪一档」的直接落点，只作用于当天；**不受下面的上限约束** |
| 3a | *自动调度*：`max(长期进度, 时间档下限)` + **抬档保护** | 「长期进度是地板，只允许涨」—— 见下 |
| 3b | *原书模板*：从**中级档起逐档下试**，取第一个装得进时间档的；**长期进度不参与，上限就是试算档位** | 「六门固定，总时长必须装进时间档」—— 与 3a 的立场正好相反 |

**时间档下限**（本版关键修正）：15/30 分钟档 → 中级档；45/60 分钟档 → 升阶档。

依据是原书第十一章原文：

> 「你真的只需做几个锻炼组……**我通常建议练习两组**，这样更有了『双保险』……三组甚至四组也可以接受。」

也就是说，**原书的日常训练量本来就是 2 组**，初级档（1 组）只是刚换到新一式时的起步门槛。
早先的实现让冷启动用户停在初级档，于是「选 60 分钟档只练 8.4 分钟」——那是实现偏差，不是原书本意。

**抬档保护**：从未训练过、或最近刚失败过的项目，下限最多抬到中级档。
依据同样是原书（第十一章「慢工出细活」）：

> 「我总是建议新手：不管你多强，都要从第一个动作开始……**给自己留出至少四周的时间**。」

所以新手第一次就是 2 组，练过一次之后 45/60 分钟档才会用上升阶档。

**为什么 3a 和 3b 立场相反？** 因为要解的问题不同：

- 自动调度解「今天状态/时间不对该练什么」，所以**长期进度是地板** ——
  时间再少也不该把你攒了几个月的进度打回去；
- 原书模板解「按原书的量把六门排满」，所以**时间档是天花板** ——
  六门是固定的，装不下只能整体降档（不然就会出现「15 分钟档排出 60 分钟训练」）。

> ⚠️ 这条天花板 2026-09-30 才补上：此前 `tierCeiling` 缺失，长期 `volumeTier`
> 一到升阶档，逐档下试就被 `max(2, floor)` 整个吃掉，**15 分钟档实测排出 60 分钟**。
> 修法与三条「平级」修正见 `DYNAMIC-PLAN-DESIGN.md` §15.4。

**组数与次数的关系**（严格区分）：

- **单组次数** = 原书 `trainingGoal` 该档的数值，**引擎不改写，界面也不能改**；
- **组数** = 该档组数（上限 4 组），再套用你在「调整」里做的 ±1 组微调。**自动调度模式**下辅助另有组数上限（15 分钟档 1 组、其余 2 组）；**模板模式下六门平级，没有这个压制**。
- **保持型动作**（倒立撑前几式）组数恒为 1，抬档只拉长单次保持时间。

### 4.4 时间账怎么算

```
热身 = 3 分钟   ← 原书：用低难度版本做 2 组（约 20 次 + 15 次），「超过 4 组只是白费力气」
训练 = Σ 各项耗时
         每项 = 60s 准备 + Σ(单组次数 × 每秒耗时) + 组间休息 × (组数 − 1)
         每秒耗时：推类 4s / 拉类 5s / 下肢 3s / 核心与后链 4s；保持型直接取秒数
放松 = 2 分钟   ← 原书明确「我从不做系统的冷却」，所以只给最低额度
余量 = 可用时间 − 热身 − 训练 − 放松
```

实测（冷启动，含热身放松），两种模式分别列：

**原书模板（默认）** —— 总时长由「装得进时间档」决定，所以到一定长度就封顶：

| 时间档 | 渐入佳境（六艺） | 初试身手（四艺） |
|---|---|---|
| 15 分 | 初级档 · 14.9 分 | 初级档 · 11.7 分 |
| 30 分 | 中级档 · 33.0 分 | 中级档 · 25.4 分 |
| 45 分 | 中级档 · 34.1 分 | 中级档 · 26.3 分 |
| 60 分 | 中级档 · 36.6 分 | 中级档 · 28.3 分 |

45/60 分档和 30 分档给同样多的量 —— **这是对的**，原书「渐入佳境」的实际内容就这么多（六门 × 2 组）。
多出来的时间是热身、放松和随时停顿的富余。**想要更多量，在「调整」里手动指定升阶档。**

**自动调度** —— 时间档决定项数与档位下限，长期进度越高排得越满：

| 时间档 | 首次 | 练到升阶档后 |
|---|---|---|
| 15 分 | 11.7 | 19.0 |
| 30 分 | 19.8 | 31.7 |
| 45 分 | 25.7 | 39.8 |
| 60 分 | 32.6 | 50.7 |

### 4.5 选谁当主训 / 辅助

> ⚠️ **本节只在「自动调度」模式下成立。** 模板模式（默认）下科目由原书清单固定，
> 六门是**平级**的：`main` / `assist` 只剩「排序位置 + 卡片视觉」的差别，
> 组数、组间休息、训练量档上限全部一致。详见本节末尾的对照表。

**主训用「优先级」，辅助用「互补性」—— 两套标准，不是摆设。**

优先级由六个因子加权（每个都归一化到 0–1）：

| 因子 | 权重 | 含义 |
|---|---|---|
| 恢复缺失度 | 0.35 | 越久没练越高，5 天封顶 |
| 完成度健康度 | 0.20 | 最近 3 次加权平均（越近权重越高） |
| 推进链权重 | 0.25 | 主练艺满分，其余 0.55 —— 这是「一门一门推进」的载体 |
| 疲劳惩罚 | 0.30 | 超过中性值 3 就扣分，且**每天衰减 40%**（否则「上周很累」会一直罚到今天） |
| 类型重叠惩罚 | 0.25 | 回溯 48 小时，看练过的项目与它的负荷重叠 |
| 停滞惩罚 | 0.15 | 连续失败的项目更快被雪藏 |

**负荷重叠矩阵**（0 = 互不干扰，1 = 完全重叠）是「六艺不是六个独立动作」的核心载体：

- `[俯卧撑][倒立撑] = 0.60` → 同为推类，禁止连续叠加
- `[桥][举腿] = 0.50` → 都压腰椎
- `[深蹲][桥] = 0.40` → 都吃伸髋 / 后链
- `[X][X] = 1.00` → **昨天练过的项目今天被自然扣满分项**，「昨天刚练过就降低优先级」因此退化成一条通用公式，而不是特例判断

辅助分 = `0.5 × 优先级 + 0.3 × (1 − 与主训的重叠) − 0.2 × 48h 内已练过的负荷`。
硬约束：与主训重叠 ≤ 0.6（禁止双推组合），辅助之间两两重叠 ≤ 0.6（防止三个辅助互相重叠）。

**训练顺序**：主训永远排第一（体力最好时做最难的动作），辅助按辅助分降序。

#### 两种模式下的「主训 / 辅助」到底差在哪

| 维度 | 自动调度 | 原书模板（默认） |
|---|---|---|
| 主训是谁 | 优先级打分第一名 | 今天科目里优先级最高的那门 |
| 辅助是谁 | 按互补性选出（有硬约束） | 模板清单里其余全部（不被重叠矩阵二次筛掉） |
| 组数上限 | 主训 4 组 / 辅助 2 组（15 分钟档 1 组） | **相同**，都为 4 组 |
| 组间休息 | 主训 `restSeconds` / 辅助短 15 秒 | **相同** |
| 训练量档上限 | 无（长期进度说了算） | 受时间档封顶（装不下就降档） |
| 卡片视觉 | 主训橙边框 + 实心序号 + Star 徽章 | 同左（仅用于标示「先做这门」） |

**为什么模板模式还要保留 `main` 这个角色？** 因为需要有人回答「先做哪一门」——
体力最好时做最难的动作，这一条与科目怎么选出来无关，两种模式都成立。
但**训练量上的差别在模板模式下必须为零**，否则就不是「六艺全练」而是「一门主练 + 五门陪跑」。

### 4.6 硬门控与例外

有些项目会被直接排除，不进候选池：

- 距上次训练不足 20 小时 → 「今天已经练过这个艺」
- 疲劳值偏高（≥4.5）且间隔 ≤48 小时
- 停滞项目强制休息 48 小时

**但绝不返回空白页**：如果过滤后候选不足 3 项，会按「最可以忍的先放回」的顺序（停滞 → 高疲劳 → 今天练过）逐条放回，并在解释面板里**如实标注哪些是放回来的**。

如果六艺全被排除，则进入**恢复日**：显示「今天建议安排恢复」，并给出「清空排除项重算」的出口。

### 4.7 一切都可解释

训练页的「为什么今天练这些」不是装饰，每一条都由真实数值填充，**换一组数据就换一句话**。包括：

- 你做的每一次调整（排除某门 / 加量 / 指定档位）都会留下一条说明
- 主训与每个辅助的入选理由（含「已经 N 天没有训练」「最近完成度 93%」「与主训负荷重叠 20%」这类具体数字）
- 时间与项数的账
- 周计划缺口的账
- 今天档位为什么是这个（**新增**：时间档抬档时会明确说出「时间档是 45 分钟，某某按升阶档安排」）
- 今天没排的每个项目，**为什么没排**（挑出扣分最多的两项因子，带真实数值）

## 5. 记录与晋级闭环

### 5.1 记录这次训练

点「开始训练 · 记录完成情况」打开抽屉，**一屏、一次提交、零折返**：

1. **逐组输入，默认预填目标值** —— 状态正常时一个数都不用改，直接提交。训练完是又累又懒得操作的时候，粒度越细越会被整段跳过。
2. **进阶条件在同一屏勾选** —— 勾满会出现一个**默认勾选**的「提交后进入第 N+1 式」，取消勾选则只记录不推进。
3. **疲劳反馈只问一次**（4 档：状态很好 / 状态不错 / 正常 / 很累），不逐动作打分。
4. **「中途停止」**复选框：体力不支 / 时间不够 / 疼痛。

> 早先版本里，「我做完了」这件事要在**两个页面各说一遍**（详情页勾条件、训练页填次数），完成一次要 5 步还得折返。v3 合并了。

### 5.2 判定规则（完成度 = 实际总次数 / 目标总次数）

| 完成度 | 判定 | 后果 |
|---|---|---|
| ≥ 100% 且疲劳 ≤ 3 | **轻松完成** | 连续达标计数 +1；连续 **2** 次 → 提议升训练量档（**需你确认**） |
| 80% – 99% | 正常完成 | 训练量维持；**达标计数清零**（所以「连续轻松完成」指的是连续两次都打满） |
| 70% – 79% | 接近但未达标 | 不计入晋级推进 |
| < 70% | 未完成 | 失败计数 +1 |
| < 60% | 明显失败 | 触发**软降量**（下次临时降一档）；若原档位 > 0，还会给出降档建议 |
| < 60% 连续 **3** 次 | **停滞** | 建议降回上一式巩固（第 7 式起只需连续 2 次） |

两条额外保护：

- **第 7 式起规则自动保守化**：晋级需要更多次达标，停滞判定更快触发；
- **难度（式号）从不自动上升**。`progressionReady` 只产生建议，写入状态必须由你点击确认。

### 5.3 闭环

训练完 → 写训练记录 + 生成判定文案 → 按你确认推进式号 → **明天打开时，今天练过的项目已被排除在候选池外，计划按新状态重算**。

> 记录时每组默认预填目标值，所以「全部达标」的情况下你不需要改任何数字 —— 一次提交就完成记录、判定与晋级确认三件事。

### 5.4 两个防漂移机制

- **进入训练页即固化当天计划**：训练过程中状态变化（比如你在别处勾了条件）不会让计划中途变形。
- **跨天自动复位**：页面挂在后台过夜，日期变了会清掉旧计划重算。

## 6. 你可能没注意到的细节

### 界面与阅读

1. **正文会自动四色高亮。** 不是手动标的标签，是一个规则解析引擎按优先级自动切分：
   - 🟠 **计量**（`3 组 × 50 次`、`保持 2 分钟`、`45°`、`80%`）→ 等宽橙块
   - 🟢 **正确做法**（`保持`、`收紧`、`锁成一条直线`…）→ 绿色加粗
   - 🔴 **风险禁忌**（`不要`、`塌腰`、`借力`、`疼痛`…）→ 红色加粗
   - **术语**（`肩胛`、`后链`、`腰椎`…）→ 点线下划线

   优先级是 `风险 > 正确做法 > 计量 > 术语`，同一位置先命中者胜 —— 这样「不要塌腰」不会被拆成绿色 + 红色两段互相打脸。

2. **进阶条件清单是自动拆出来的，没有额外维护数据。** 原文写作「`3 组 × 50 次`，全程直体成线、下沉至胸部近墙、无耸肩借力。」——按中文逗号/顿号一切，正好是「1 条数量目标 + N 条质量要求」，两种类型用不同图标区分。

3. **常见错误也是自动拆的**：原文格式固定为「错误表现 —— 纠正方法」，界面渲染成**红块（错误表现）+ 绿块（纠正方法）**配对呈现，不只给一个「错」字。

4. **训练目标三档用了递进视觉**（实心高亮的「当前档位」徽章），不是三个等权重格子 —— 因为它就是训练量阶梯本身。

5. **图位目前全是占位。** 页面里所有「应该有图」的位置都是固定宽高比的空位（标注「图片待补充」），**没有任何实际图片**。好处是布局高度恒定、不会因为补图而抖（CLS = 0），且补图时只需传一个 `src`，页面结构不改。
   - 十式详情页用的是**紧凑条**（约 62px 高），不是大灰框 —— 早先版本 3:2 的空框在 375px 手机上占 250px 高，等于把首屏黄金位置全给了「没做完」的观感。

6. **颜色的用法是刻意的。** 颜色只用来标识「这是哪个对象/模块」，**不用来表达「谁更重要」**。优先级由尺寸、位置、留白承担。
   - 六门艺各有固定色相（俯卧撑永远是橙、深蹲永远是绿……），跨页面一致；
   - 模块色调只有 5 个语义：橙=行动 / 蓝=数据 / 绿=正确 / 红=风险 / 紫=引导；
   - 同一组平级选项（时间档 15/30/45/60）形状完全一致，只区分选中与未选中。

7. **深色主题下按钮文字用的是 `text-bg` 而不是 `text-white`。** 浅色主题的橙色配白字是 5.2:1，但深色主题的橙色是亮橙，配白字只剩 2.2:1。用 `text-bg`（浅色下≈白、深色下≈近黑）一套写法同时满足两套主题。

8. **首屏不会闪烁。** `<head>` 里有一段同步内联脚本，在 React 挂载之前就读取主题偏好并给 `<html>` 加上 `dark` 类。

### 状态与存储

9. **全站三个 `localStorage` 键**：
   - `theme` —— 主题偏好
   - `disclaimer-dismissed` —— 顶部安全提示条是否已关闭（**独立键**，与主题互不干扰）
   - `cc.training.v1` —— 训练状态**单键原子存储**（避免多键写入不一致；键名里的 `v1` 是历史遗留，内部版本号已到 `v2`）

10. **存储有版本迁移，且不丢数据。** v1 → v2 时，旧版固化的「今日计划」因为缺字段被丢弃（次日重算，零损失），但**训练历史与六艺进度全部保留**。

11. **训练会话保留上限 200 条**，超出裁剪最旧的；每个艺只保留最近 5 条摘要用于算完成度。

12. **隐私模式 / 配额超限 / 脏数据全部静默降级**，不会抛异常阻断页面 —— 所有读写都包了容错。

### 工程与运维

13. **`/dev/ui` 是组件视觉自检页，只在开发环境存在。** 生产构建时 `import.meta.env.DEV` 被折叠为 `false`，整段代码被剔除，产物里完全不含它。

14. **SEO 覆盖到每一页。** 每页动态设置 `title` 与 `description`；`sitemap.xml` 由构建脚本**从数据源派生**（4 个静态页 + 6 个艺页 + 60 个式页 = 70 条），内容层增删动作时 sitemap 自动跟随。

15. **深链刷新不会 404。** 托管侧配了 SPA 回退：`/arts/pushups/5` 这种路径刷新时由前端路由接管。

16. **构建带两道守卫**：`check-lock` 校验依赖锁文件一致（防止线上 `npm ci` 失败）；单测里的 `designTokens` 守卫会静态扫描源码，拦截「Tailwind 透明度修饰符不是 5 的倍数」这类**不报错但静默失效**的类名。

### 站内没有的东西（也算细节）

17. **没有搜索、没有收藏、没有分享按钮。**
18. **没有账号、没有云同步、没有服务端。**
19. **没有 PWA / 离线缓存**，断网打不开。
20. **没有组间休息计时器** —— 这是目前最明显的一个缺口，详见 §9。
21. **没有导出 / 导入数据的功能** —— 换设备只能从头开始（见下节）。

## 7. 手把手：一天怎么用

### 剧本 A · 第一次打开（约 1 分钟）

1. 打开首页，看到「先花 20 秒设好训练节奏」→ 点**开始设置**。
2. 回答三个问题：**每周练几天**（2–6 天）、**每次多少时间**（15/30/45/60 分）、**六艺大致水平**（完全新手 / 练过一阵 / 有训练基础）。
   - 系统按这三项反推初始式号与默认时间档。**逐项自报当前式号是可选的，能跳过 —— 留白比填错好。**
3. 点「生成我的第一个训练计划」，落在**训练页**。
4. 你会看到：主训 1 项 + 辅助若干 + **时间账四格** + 一句话摘要。往下翻能展开「为什么今天练这些」。
5. 这时先别急着练 —— **建议先去 `/principles` 读一遍**，尤其是第 2、3 节（不力竭、组间休息）。

> 新手实测：60 分钟档第一次会给到约 **33.7 分钟**（含热身放松）。练过一次之后，同样的时间档会升到约 **53.7 分钟**。这是刻意的保守起步。

### 剧本 B · 一个标准训练日（约 40 分钟）

**① 出门前 / 上班摸鱼时看一眼**

打开首页 → 「训练安排」告诉你要练什么、大概多久。想改就点「开始训练」进训练页。

**② 到训练页，先确认三件事**（点右上角「调整」）

- 今天到底有多少时间？→ 改**时间档**（会连带重算项数与训练量档）
- 有没有哪门今天完全不想练？→ 点一下**排除**它，系统用同一套规则重算剩下的
- 今天想练哪个档？→ 选**初级 / 中级 / 升阶**。想试更高档不用等系统批准，直接选

**③ 看计划卡**

每张卡上有一眼能读的三样：**档位徽章**（初级档/中级档/升阶档）、**训练量**（`2 组 × 25 次`）、**组间休息参考值**。不确定动作怎么做，点卡上的「看动作要领」跳到详情页。

**④ 开练**

热身 **3 分钟**：用你正要练的动作的**低难度版本**做两组（第一组约 20 次、第二组约 15 次），用一半力气。做完应该有点兴奋，而不是精疲力竭。

然后按顺序做主训、辅助。**组间休息参考值只是参考** —— 判据是「下一组能不能全力以赴」。没恢复就多休息；如果要休息超过 5 分钟，起身走动几步别让身体冷却。

> 每组都留一点余力。姿势开始变形、速度失控、靠摆动借力 —— 在这之前就停。

**⑤ 练完记录**（约 30 秒）

点「开始训练 · 记录完成情况」：

- 每组**已经预填目标值**。全部达标 → 一个数都不用改；
- 有一组做少了 → 用 −/+ 调，数字会变红提示；
- 顺手把**进阶条件**勾了（勾满会自动出现「提交后进入下一式」，默认勾选）；
- 选一下**练完感觉怎么样**（4 档）；
- 中途停下过就勾「中途停止」。

**⑥ 提交**

页面顶部立刻显示判定结果（「完成度 100%，很轻松。再连续达标一次即可提升训练量」这类），并说明「难度变更需要你确认，不会自动跳级」。

### 剧本 C · 状态不好 / 今天只有 15 分钟

1. 训练页 →「调整」→ 时间档选 **15 分**。项数自动降到 2 项（1 主 + 1 辅），辅助组数上限压到 1 组，组间休息降到 60 秒。
2. 还有点累？把**训练量**切成「减一组」（每项少做一组）。
3. 完全不想动？把六门艺全点掉 —— 系统会给出**恢复日**方案，明确说「今天不安排训练，恢复也是训练的一部分」。
4. 练完记录时，疲劳选「很累」。这会让明天的计划更保守（六艺疲劳均值 ≥4.0 时自动少排一项）。

### 剧本 D · 想往上冲

**情况一：想在同一式里练更多。**
「调整」→ 训练量档选**升阶**（或时间档切到 45/60 分），组数直接上去。练完如果完成度 ≥100% 且疲劳 ≤3，系统会开始计数，连续两次后提议正式升档。

**情况二：想换下一式。**
去该式的详情页，把**进阶条件逐条勾满**（数量目标 + 质量要求），然后点「完成本式 · 进入第 N+1 式」。这是唯一让式号上升的方式。

**情况三：一直上不去。**
连续 3 次完成度 <60% 会被判定停滞，系统建议降回上一式巩固。详情页每个动作也有**降阶方案**板块，直接告诉你退到哪一式。

### 剧本 E · 换手机 / 清理浏览器数据前

**⚠️ 目前没有导出功能。** 训练记录只存在当前浏览器里，清数据、换设备、换浏览器都会丢。唯一的办法是不要清这个站点的浏览器数据。

## 8. 数据与隐私

- 所有训练记录、进度、打卡状态、主题偏好**只写在本机浏览器的 `localStorage`**，不上传任何服务器。
- 没有账号、没有 cookie、没有埋点、没有第三方脚本（唯一的网络请求是加载站点自身的静态资源）。
- 首次访问会看到顶部一条**安全提示条**，可以关掉，关闭状态也会被记住（独立存储键）。
- 训练会话最多保留 200 条，更早的会被裁剪。

## 9. 已知缺口 · 按优先级

| 优先级 | 缺口 | 影响 |
|---|---|---|
| **高** | **没有组间休息计时器** | `restSeconds` 只在卡片和提示里以文字显示，全站没有任何倒计时/到点提醒（代码里 grep 不到一个 `setInterval`）。训练时得另外开秒表 —— 这是目前最影响训练现场体验的缺口。 |
| **高** | **没有数据导出 / 导入** | 换设备或清缓存即抹掉全部训练历史，且无法补救。 |
| 中 | **60 式没有任何图片** | 全是图位占位。动作指导靠文字，进阶动作（倒立撑、桥系）没有图确实吃力。 |
| 中 | **没有搜索** | 60 式只能靠「六艺 → 十式」逐层点进去找到。 |
| 中 | **没有 PWA / 离线** | 地铁、健身房信号差时打不开。 |
| 低 | **原书五套计划只做了两套** | 「炉火纯青」（一周 6 天每天一艺，每天仅 6–7 分钟，与本站时间档不匹配）、「闭关修炼」（需苦练一年以上、每周 6–7 小时）、「登峰造极」（原书明说是耐力特化、**不提升力量**）三套未实现，理由见 `lib/plan/config.ts` 的注释。 |
| 低 | **`system` 主题未启用** | 类型层已预留，但暂不跟随系统深浅色，默认浅色。 |
| 低 | **搜索友好的静态预渲染缺失** | 是纯客户端 SPA，首屏内容靠 JS 渲染；`sitemap` 与 meta 已做，但对爬虫仍不算友好。 |

## 附：术语速查

| 术语 | 含义 |
|---|---|
| **艺** | 六个动作门类：俯卧撑、深蹲、引体向上、举腿、桥、倒立撑 |
| **式** | 每门艺里的 10 个递进动作之一，如「第 5 式 标准俯卧撑」 |
| **训练量档** | 同一式内的三档训练量：**初级（1 组）/ 中级（2 组）/ 升阶（2–3 组，按该式阶梯）**，计划页可在「调整」里三选一 |
| **时间档** | 你今天有多少时间：15 / 30 / 45 / 60 分钟 |
| **主训 / 辅助 / 加练自选** | 今天优先级最高的那项 / 补足负荷类型的若干项 / 时间有富余时才考虑的可选项 |
| **负荷重叠** | 两个动作练到同一批肌肉的程度，用于避免连续叠加同类刺激 |
| **软降量** | 一次性临时降量，不写回长期档位 |
| **停滞** | 连续多次完成度过低，系统建议降回上一式 |
| **恢复日** | 六艺全被排除时给出的兜底方案，绝不留空白页 |
