# 今日动作速览（翻页卡片）· 设计文档

> 版本 v1.0 · 2026-10-02 · 纯前端，零新增依赖
>
> 本文档只做设计，不含实现。对应需求：**第一次做某个动作时不用逐个点进详情页**，
> 有一个可左右翻页的界面，一页一个动作，比详情页精简。

---

## 0. 问题与定位

**现状痛点**：今天的计划有 2–6 个动作，其中不少是第一次做。要看清楚「怎么摆、怎么动」，
必须逐个点进 `/arts/:artSlug/:stepNo` 详情页 —— 一次 4 个动作 = 8 次点击 + 8 次返回，
而且详情页信息量远大于此刻所需（打卡卡、训练目标三档、进阶标准原文、肌群、降阶、常见错误……）。

**定位**：今日计划的**横切视图**。页序 = 今天引擎排给你的训练顺序，一页一个动作，
只回答三件事：**长什么样 / 今天做多少 / 关键几点**。

**三条边界（明确不做）**：

| 不做 | 理由 |
|---|---|
| 不承担打卡与记录 | 那是 `LogSheet` 的职责。一个界面只干一件事，两处都能改状态必然产生不一致。 |
| 不是内容库浏览器 | 页序来自今天的 `DailyPlan`，不是六艺 1→10 的顺序，也不提供跨艺跳转。 |
| 不新增任何文案 | 全部取自既有字段（原书原文 + 引擎产物）。站内约定：`steps`/`keyPoints`/`regression` 不得推导，见 `MEMORY.md` §1.7。 |

## 1. 信息架构（一页的内容）

`精简版`（已确认）：一屏看完，不出现上下滚动。

| 位置 | 内容 | 数据来源 | 精简规则 |
|---|---|---|---|
| 身份行 | 序号 / `艺名 · 第 N 式` / 动作名 / 难度徽章 | `PlanItem` + `Move.difficulty` | 艺名与式号压在动作名上方一行小字 |
| 动作图 | 起始姿势 + 结束姿势（双图各半宽） | `moveFigureSrc(slug, stepNo, 1\|2)` | 复用 `MoveFigurePair`，含点开大图 |
| **今天的量** | `2 组 × 25 次` / 保持型 `2 组 × 20 秒` | `PlanItem.sets` · `targetPerSet` · `metric` | 本页唯一实心数字，`formatVolume()` 产出 |
| 量副行 | 组间休息参考 N 秒 | `PlanItem.restSeconds` | 右对齐小字。原书不给秒数，措辞必须保留「参考」二字 |
| 怎么做 | `steps` 前 3 条（有序） | `Move.steps`（← 原书「动作」段） | 超过 3 条时脚注「共 N 步 · 详情页看全」 |
| 注意 | `keyPoints` 前 1–2 条 | `Move.keyPoints`（← 原书动作/解析/稳扎稳打） | 若 `commonMistakes` 非空，则改为 `keyPoints[0]` + `commonMistakes[0]`（原书点名的错误优先级更高） |
| 太难就降阶 | `regression` 原文 | `Move.regression`（← 原书「稳扎稳打」） | **默认折叠**（`<details>`），第一次做的人需要它，但不该占常驻版面 |
| 风险提示 | `riskNote` | `Move.riskNote`（本站标注） | **常驻不折叠**。安全信息不做折叠 |
| 页脚 | `看完整动作要领 →` | `moveHref(skill, stepNo)` | 唯一的出口，跳详情页 |

**页面级空态**：`plan.kind === 'recovery'` 或 `items.length === 0` 时，整页显示一句说明 +
回训练页的按钮，不渲染轨道（避免一个空轨道）。

### 1.1 关于「一屏」——实测结论（2026-10-02 无头 Chrome，390×844）

实测卡片高度 **834–1132px**，**比一屏略高**。这是内容量决定的，不是排版问题：
真实数据里 `steps` 有三条（每条 2–3 行）、`keyPoints` 两条、桥与倒立撑还有 `riskNote`。
把它压到一屏只有两条路 —— 砍内容，或做嵌套滚动区，两条都不接受。

所以「一屏」的验收标准定为：

> **首屏（不滚动）必须完整包含「身份行 + 双图 + 今天的量 + 怎么做开头」；**
> 「注意 / 降阶 / 页脚」允许纵向滚动。

首屏能被看到的是最需要的信息（这一式长什么样、今天做多少），这也是「第一次做」时唯一
必须立刻对上号的三件事。

**卡片高度由内容决定，不做等高**（轨道用 `items-start`）。理由：某一页展开「降阶」后内容会
明显变长，若强行等高，其余每一页都会多出一大片死空白。轨道容器本身仍由最高的一页决定高度，
所以翻页时页码条不会上下跳。

**页头只留两行**（标题 + 日期），不放面包屑 —— 底部标签栏的「训练」一直可见，返回路径不缺，
而面包屑要占掉手机上近 50px 的首屏高度。

## 2. 交互设计

### 2.1 翻页方式（三通道，互为兜底）

| 通道 | 实现 | 说明 |
|---|---|---|
| 手势 | 横向 `overflow-x: auto` + `snap-x snap-mandatory` + `snap-center` | 惯性、回弹、触控全部由浏览器给，零 JS |
| 按钮 | 页脚 `‹` `›`（视觉 40px，触控区 ≥44px） | 首/末页 `disabled`，且带 `aria-disabled` 而非只变灰 |
| 键盘 | 容器 `tabindex="0"`，`←` `→` 翻页，`Home` `End` 跳首末 | `overflow` 容器默认**不可聚焦**，不加 `tabindex` 键盘用户根本滚不动 |

### 2.2 位置与状态

- **URL 同步**：当前页写入 `?i=N`，用 `history.replaceState`（**不新增历史条目** ——
  否则按一次返回只退一页，用户要退 4 次才能回训练页）。刷新、从详情页返回时保持原页。
- **进入时定位**：URL 带 `?i=N` 时静默定位到该页（无动画），否则第 1 页。
- **纵向回顶**：**按钮 / 键盘**翻页时把页面收回轨道顶部 —— 卡片比一屏高，用户滚到底看过
  「注意 / 降阶」后按下一页，若继承滚动位置，眼里直接是页面中段，等于「翻过去却看不见头」。
  手势翻页**不**回顶：手就贴在轨道上，强行回顶会跟手指打架。
- **连续翻页**：相对翻页的基准取「待到达的目标下标」而不是渲染出来的 `index` ——
  `setState` 是异步的，用 `index` 做基准会让连点两下只前进一页（键盘连按同理）。
- **页码**：`● ● ○ ○` + `2 / 4` 数字双通道。数字供读屏与色觉障碍用户。
- **播报**：`aria-live="polite"` 只在按钮 / 键盘翻页时立即播报；手势滚动改为**停下 500ms 后**
  播报一次（逐帧播报会变成噪音）。
- **图片按需**：卡片图片沿用 `MoveFigurePair` 的 `loading="lazy"`。横向轨道里非当前页的图
  与视口不相交，浏览器不会提前加载；若真机上发现进入即拉满 12 张图，再改成只渲染 `current ± 1`。
- **动效**：只用 `transform` / `opacity`，200–250ms。不引入任何循环动画。

### 2.3 无障碍要点（WCAG 2.2 AA）

- 轨道 `<ul aria-label="今天的动作">`，每页 `<li role="group" aria-roledescription="幻灯片"
  aria-label="第 2 页，共 4 页：肩倒立深蹲">`。
- 每页唯一的标题用 `<h2>`，动作名用 `<h3>`，不跳级。
- 焦点可见：所有可聚焦元素有 `focus-visible` 环，**不用 `outline: none`**。
- 颜色不作唯一通道：艺身份同时有文字「深蹲 · 第 1 式」；难度是「文字 + 颜色」双通道
  （复用 `DifficultyBadge`）。
- 正文 ≥16px / 行高 ≥1.7；量条数字用 `tnum` 等宽。
- 艺色只用于序号徽章、分隔条这类小面积装饰，正文永远是 `text-text`。

## 3. 技术方案

### 3.1 文件清单

| 文件 | 职责 |
|---|---|
| `src/lib/plan/deck.ts` | 纯函数 `buildDeck(plan): DeckItem[]` —— 把 `DailyPlan` 摊平成页数组，并完成「前 3 条 / 前 1–2 条」的截断规则。**可单测、无副作用** |
| `src/lib/plan/deck.test.ts` | 覆盖：数量截断、`commonMistakes` 优先规则、`move` 取不到时的降级、空计划 |
| `src/components/plan/MoveDeck.tsx` | 横向轨道 + 翻页控制 + URL 同步 + 播报 |
| `src/components/plan/MoveDeckCard.tsx` | 单页卡片（纯展示，接收 `DeckItem`） |
| `src/pages/TodayMoves.tsx` | 路由页：取 `plan` → `buildDeck` → 空态判断 |

改动：

| 文件 | 改动 |
|---|---|
| `src/App.tsx` | 加路由 `/plan/today` |
| `src/pages/Plan.tsx` | 加「先看今天的 N 个动作」入口 |
| `src/pages/Home.tsx` | 加同页入口（见 §4） |

复用（不新写）：`MoveFigurePair`（含 `ImageLightbox`）、`DifficultyBadge`、`RichText`、
`artTheme`、`moveFigureSrc`、`formatVolume`、`Section`、`Button`、`Skeleton` 类占位块。

### 3.2 数据流

```
useTraining().plan  ──buildDeck()──▶  DeckItem[]
                                        ├─ item: PlanItem        （今天的量、顺序、角色）
                                        ├─ move: ResolvedMove|null（内容字段）
                                        ├─ steps: string[]        （≤3 条）
                                        └─ notes: string[]        （≤2 条）
```

`move` 取不到（`getMove(skill, stepNo)` 返回 `undefined`，理论上不该发生）时**降级而非抛错**：
该页仍渲染身份行 + 量条，图与文案区显示「这一式的资料暂时取不到，去详情页看看」。
整页绝不因单项数据缺失而白屏。

### 3.3 样式红线（改这一页前必读）

1. **禁止出现 `dvh` + `flex-1` 的高度链。** 轨道高度跟着内容走，纵向滚动交给 `body`，
   不套嵌套滚动区 —— 2026-10-02 手机白屏事故的根因正是这条链（`MEMORY.md` §1.5）。
   卡片用 `min-h-[420px]` 这类固定下限保证「一屏感」，**不用** `min-h-[*dvh]`。
2. **iOS 左边缘右滑 = 浏览器返回**，会和「右滑翻上一页」冲突。对策：轨道左右各留 16px
   内边距（卡片不贴屏边）、`overscroll-behavior-x: contain`、按钮兜底。
   这是已知取舍，不是 bug。
3. 透明度修饰符只能取 5 的倍数（`bg-accent/8` 静默失效，有守卫测试）。
4. 深色主题不用 `text-white` 配亮色底，统一 `text-bg`。
5. 页脚要让开底部导航：用既有的 `pb-nav`，不要自己算高度。

## 4. 入口设计

| 位置 | 形态 | 说明 |
|---|---|---|
| 训练页「今天练这些」 | 在「开始训练 · 记录完成情况」**上方**加一个次要按钮「先看今天的 N 个动作」 | 正对「练前过一遍」的动线；不与「调整」抢板块标题旁的位置（移动端两个小按钮并排会挤） |
| 首页「训练安排」卡 | 把现有那行说明文字（「时间、换方案、逐组记录都在训练页」）**替换为**一行文字链接「先看今天的 N 个动作 →」 | 首页的原则是「只回答今天做什么、不承担操作」，所以**不新增按钮、不新增色块**，只占一行已有文案位。主按钮仍是唯一的实心按钮 |
| `PlanItemCard` | 保留现有「看动作要领 →」不变 | 单点查询仍走原路径 |

## 6. 本期不做

- 打卡 / 勾选进阶条件（`LogSheet` 已覆盖）
- 在速览页直接「开始训练」（跨路由打开抽屉，状态传递复杂，收益低）
- 全屏沉浸形态（隐藏顶栏与底部导航）—— 需自建滚动锁与视口高度，正是踩过的雷区
- 图片全量预加载（120 张 6.2 MB，SW 已按需缓存，不需要）
- 自动播放 / 轮播定时器（用户要的是「看」，不是「被推着走」）
