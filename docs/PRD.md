## v1.2 变更记录

**变更原因（用户反馈原文）**：
> "这些图片我不需要写实的真人，重点是保证动作指导的准确性，可以用简约的示意图也行"

**变更解读**：v1.1 采用「AI 生成的写实人物插画（共 66 张）」作为图片方案。用户明确否定**写实真人**路线，把图片方案的**首要目标由「视觉风格统一」改为「动作指导的准确性」**，并允许改用**简约示意图**。据此，图片方案**整体替换为数据驱动的简约矢量示意图**（非写实）。

**变更依据**：

| # | 依据 |
|---|---|
| 1 | **写实 AI 图无法保证动作准确性**——已实测发现首轮生成的「单腿深蹲（深蹲第 10 式）」姿势错误（臀部停在膝盖高度，实为第 8 式「单腿半深蹲」的深度）。作为**动作指导图**会直接误导读者，这是本网站最不能接受的问题。 |
| 2 | AI 生成图片涉及《人工智能生成合成内容标识办法》(2025-09-01 施行) 的**标识义务**，且生成工具会强制打**水印**；改自绘矢量图后此问题自然消除。 |
| 3 | 矢量示意图的动作姿态由**我们指定的关节角度**决定，**准确性可控、可校验**。 |
| 4 | 附带收益：矢量图**体积极小、随主题自动换色、任意缩放不糊、可标注关键角度与发力方向**。 |

**关键定性**：**示意图不是装饰，是动作指导的组成部分。** 这决定了验收标准——「示意图呈现的姿态必须与文字步骤描述一致，且不得产生误导」。

**变更范围**：

| # | 变更点 | 涉及章节 |
|---|---|---|
| 1 | **图片方案整体替换**：删除「AI 生成写实插画 66 张」的全部内容（数量、统一 prompt 风格锚点、写实要求、AI 生成标识、水印处理、WebP 格式与体积上限、图片批次策略），改为「每式一张矢量示意图 + 详情页『起始 / 中段 / 终点』三帧分解并排图」 | §1、§7.5、§7.7、§9 |
| 2 | **新增示意图 P0 需求**（覆盖率 100%、随主题适配、图注 + alt、禁写实、标注克制） | §5（P0-17/P0-18/P0-19） |
| 3 | **成功标准更新**：移除「图片交付 66 张」，新增示意图覆盖率 / 图文一致性核对 / 双主题可辨识指标 | §2.2 |
| 4 | **P0-11 改写**、P0-12 保留设计系统（去图片风格表述） | §5 |
| 5 | **待确认问题收口**：作废的图片相关问题（Q7）标注已关闭 | §8 |
| 6 | **内容安全补一条**：示意图与文字描述不一致时以文字步骤为准，并明确站长 / 内容维护者核对责任 | §9 |
| 7 | **原始需求复述**同步修正图片描述 | §1 |

**不变项（本次未改动）**：第 6 章 60 式核对表（内容已核实）、7 个页面的信息架构、十式详情页 13 字段规格（示意图作为附加内容，**不破坏**既有 13 字段）、可访问性量化指标（对比度 / 字号 / 行高 / 触控目标）。

### 2.3 用户故事（3 个）

**US-1｜新手选动作**
> 作为一个**零基础健身新手**，我想知道「完全做不动俯卧撑该从哪个动作开始」，以便不受伤、能真正上手。
- 价值：通过「第一式」入口 + 难度等级标识，把我直接带到可执行的最低门槛动作。

**US-2｜进阶者查标准**
> 作为一个**已能完成标准俯卧撑的练习者**，我想知道「做到什么程度算过关、下一式是什么」，以便知道何时该升级难度。
- 价值：通过「进阶标准 + 上一式/下一式链路」，把升级决策变成一次点击。

**US-3｜学习者对照练姿势**
> 作为一个**在训练中临时查阅姿势的人**，我想在手机上快速看到某式的分解步骤和常见错误，以便当场纠正动作。
- 价值：移动端优先 + 结构化步骤/错误清单，让手机成为随身教练。

### 6.3 各艺训练目标速览（**原书三档** · 供详情页 `trainingGoal` / `progressionStandard` 参考）

> **形态**：计次式（57 式）为「**N 组，各 M 次**」，单侧动作在次数后标「（每侧）」；**倒立撑前三式为计时式**，只给时长（N 秒 / N 分钟），无组次。

## 7. UI 设计说明（移动端可读性优先 · 浅色默认）

> **本章为 v1.1 整体重写（视觉方向 / 可访问性），v1.2 曾整体替换图片方案，v1.3 将 §7.7 重写为「图位占位规范」。** 核心原则：**移动端可读性优先** —— 一切视觉决策服务于「在手机上看清动作、读懂要点」。
> 「硬核」气质**保留**，但**改由排版层级**（粗体大标题、编号体系、等宽数字）传达；**不得**再依赖暗色底与低对比灰字来营造氛围。

### 7.1 设计语言与核心原则

| 原则 | 说明 |
|---|---|
| **可读性优先** | 任何视觉选择（颜色、字号、间距、装饰）都要先过「手机上是否看得清」这一关；可读性冲突时，装饰一律让步。 |
| **默认浅色主题** | 默认 **浅底深字**（浅色背景 + 深色文字），保证户外 / 强光下的手机屏幕依然清晰。 |
| **深色模式可选** | 保留深色主题作为**手动切换**模式（因设计 token 集中管理，增量成本低）；**默认不启用**。 |
| **色彩仅作语义** | 颜色只用于**语义区分**（难度等级 / 正确做法 / 常见错误 / 强调），**不作装饰**。 |
| **气质靠排版** | 硬核感由粗体大标题、有序编号、等宽数字传达；**首版无图片**，图位保持中性克制（见 §7.7）。 |

**明确移除**以下影响可读性的装饰性元素：
水泥 / 钢铁纹理、胶片颗粒（film grain）、重阴影（drop shadow / 发光）、低对比灰字、纯装饰性色彩、大圆角糖果风。

### 7.3 可访问性与排版规范（**P0 验收指标**）

#### 7.3.1 可量化可访问性标准

| 指标 | 要求 | 备注 |
|---|---|---|
| 移动端正文字号 | **≥ 16px** | 小于 16px 不得用作正文 |
| 次要文字（英文名 / 元信息）字号 | **≥ 12px**，且**不得承载关键信息** | 关键信息必须用正文级字号 |
| 正文行高 | **≥ 1.7** | 中文密排易读性所需 |
| 文字对比度（正文） | **≥ 4.5:1**（WCAG AA） | 见 §7.2 标注值 |
| 文字对比度（大字号） | **≥ 3:1** | 大字号定义：≥18.66px 粗体 或 ≥24px |
| 非文字关键元素对比度（边框 / 图标） | **≥ 3:1** | 图标、输入框描边、聚焦态 |
| 触控目标尺寸 | **≥ 44 × 44 px** | 所有可点击元素 |
| 桌面单行文本宽度 | 限制在约 **70–80 字符** | 避免长行难读（`max-width` 约束正文容器） |

#### 7.3.2 字体层级（**移动端优先，字号不小于表内下限**）

| 层级 | 移动端字号 / 字重 | 桌面字号 / 字重 | 用途 |
|---|---|---|---|
| Display | 32–40px / 800 | 40–56px / 800 | 首页 Hero 主标题 |
| H1 | 26px / 700 | 28–32px / 700 | 页面标题 |
| H2 | 20px / 700 | 20–22px / 600 | 章节标题 |
| H3 | 18px / 600 | 16–18px / 600 | 卡片标题 / 字段标签 |
| Body | **16px** / 400（行高 **1.7**） | 16px / 400（行高 1.7） | 正文 |
| Caption | 12–13px / 400 | 12–13px / 400 | 英文名 / 元信息 / 序号（**不承载关键信息**） |

- 标题用**无衬线粗体**（Inter + 中文思源黑体），数字 / 序号 / 英文名用**等宽字体**（JetBrains Mono）——这是「硬核技术感」的主要来源（替代暗底）。
- 中英文混排：中文名为主（正文字号），英文名以 Caption + `--text-muted` 辅助展示。

### 7.4 排版与信息层级（替代靠颜色 / 暗底做区分）

**用「字号 / 字重 / 留白 / 编号」而非颜色来构建强层级。**

| 信息块 | 层级手段 |
|---|---|
| **章节标题**（分解步骤 / 要领要点 / 常见错误 / 进阶标准） | H2 粗体 + 上方大留白（如 32px）+ 左侧 4px 语义色竖条 + **有序编号**（如「① ② ③」或「01 02」等宽数字） |
| **分解步骤** | **有序列表 `<ol>`**，序号用大号等宽数字（如 24px `--accent`），步骤文字 16px/1.7，步骤间距 ≥ 12px |
| **要领要点** | 无序列表，项目符号用 `--success` 色小方块（**语义**：正确做法），条目间留白拉开 |
| **常见错误** | 每条为「错误表现 —— 纠正」，`--danger` 色标签 + 图标（**语义**：警示），与正确做法形成视觉对照 |
| **进阶标准** | 独立强调块（`--surface-2` 底 + `--accent` 左边框），加粗数字（组×次数）用等宽字体突出 |
| **整体节奏** | 块与块之间用**明显留白**（≥ 24px）分隔，配 H2 与编号，形成「一眼定位」的分块感；**不靠深色底或彩色大色块** |

> 每种颜色都对应固定语义（`--success`=正确 / `--danger`=错误 / `--accent`=强调 / 等级色=难度），**不做纯装饰用色**。

**十式详情页 · 移动端阅读顺序与折叠策略**：

用户最可能临时查的目标是「**这一步怎么做**」和「**常见错误是什么**」，因此：

1. **阅读顺序（自上而下）**：
   ① **图位（单一主图，3:2）** → ② 动作名 + 难度标签 + 序号 → ③ 一句话描述 → ④ **页内锚点条** → ⑤ **分解步骤（默认展开、置前）** → ⑥ 要领要点 → ⑦ 常见错误 → ⑧ 进阶标准 / 训练目标 → ⑨ 降阶方案 → ⑩ 发力肌群 → ⑪ 上一式 / 下一式。
2. **页内锚点条**（吸顶）：提供「分解步骤 · 要领 · 常见错误 · 进阶标准」四个锚点，**一键滚到对应块**——满足「临时查某一块」的最高频诉求。
3. **折叠策略**：
   - **默认展开**：动作描述、分解步骤（最高频，必须免点击可见）。
   - **默认展开但可折叠**：要领要点、常见错误、进阶标准（核心查阅内容，优先可见）。
   - **默认折叠（点击展开）**：降阶方案、发力肌群等次要字段，减少首屏长度。
4. **桌面端**：正文容器 `max-width` 约束为约 70–80 字符宽；可启用「左侧图位（单一主图） / 右侧信息」双栏，但保持同样的信息顺序。

### 7.5 卡片与网格布局

- **六艺网格**：桌面 3×2，平板 2×3，移动 1 列；卡片 = 封面图位 + 艺名 + 定位语；封面图位比例 **3:4**（竖版）。
- **十式列表**：横向编号阶梯 / 网格；每项含缩略图位（比例 **1:1**）、序号徽章、中英文名、难度标签（用 §7.2.1 等级色 + 文字，**色不是唯一区分手段**）。
- **十式详情**：图位（**单一主图，3:2**）上、信息下；字段用「标签 + 内容」分块卡片（见 §7.4）。
- 卡片统一用**细描边**（`--border`）而非阴影来区分层级；圆角克制（4–8px）；**不使用纹理装饰**。

### 7.6 移动优先与断点

| 断点 | 宽度 | 表现 |
|---|---|---|
| sm | < 640px | 单列，汉堡导航，卡片全宽，**正文字号 ≥ 16px** |
| md | 640–1024px | 2 列网格 |
| lg | ≥ 1024px | 3 列网格，固定顶栏，正文行宽受限 |

> **本节为 v1.3 整体重写**：删除 v1.2 的「矢量示意图」全部内容，改为 **图位占位**。

#### 7.7.4 布局稳定性（**P0-11 核心验收**）

- 图位须以**固定比例容器**（如 CSS `aspect-ratio`）实现，使**有无图片时布局高度完全一致**——**不塌陷、不抖动**。
- 验收：图位空置（无图）时页面高度与填充图片后**一致**；页面加载 / 切换主题过程中**无可见位移**（**CLS ≈ 0**）。

#### 7.7.5 将来补图的替换路径（**不改页面结构**）

- 约定**文件名规则**，使补图时仅替换资源、**无需改动页面结构或组件**。路径规则如下（**本路径约定以 `docs/ARCHITECTURE.md` §5.5 为唯一真源**，两份文档以架构文档为准，不得分叉）：

| 场景 | 文件名规则 | 目录 |
|---|---|---|
| 六艺封面 | `{artSlug}.webp`（如 `pushups.webp`） | `public/images/arts/` |
| 十式主图 | `{artSlug}-{NN}.webp`（如 `pushups-05.webp`，**NN = 二位补零 stepNo**） | `public/images/moves/` |
| 列表缩略 | `{artSlug}-{NN}-thumb.webp` | `public/images/moves/` |

> **术语说明**：十式在代码中为 **Move**（`Move` 类型 / `MOVES_PER_ART` / `moveSlug()`），故目录用 **`moves`** 而非 `steps`，避免引入第二套命名。

- **「不改页面结构」的实现机制（与架构文档对齐）**：`FigureSlot` 的容器（**比例 + 圆角 + 主题底**）**首版即为最终形态**；补图时只是**往同一容器内塞入 `<img>`**，`src` 作为**可选 prop** 传入。因此**页面数据契约与组件层级均不变**——本承诺成立。具体见 `docs/ARCHITECTURE.md` §5.5；PM 仅约束「不破坏页面结构与比例」。

#### 7.7.6 尺寸 / 格式 / 体积要求（**补图阶段约束，首版不实施**）

> 以下为**将来补图时**的约束，**首版不实施**，仅作为补图阶段的验收依据留存。

| 项 | 约束（补图阶段） |
|---|---|
| 位图格式 | WebP（次要 PNG 兜底） |
| 分辨率 | 按 2× 屏适配（主图 ≥ 1200px 宽，缩略 ≥ 600px 宽） |

#### 7.7.7 主题适配（**P0-17**）

- 图位**在浅色与深色两套主题下都必须与页面协调**，**不得出现「浅底看不见」**。

- **验收**：在浅色与深色主题下分别抽检全部图位；作为非文字关键元素，其与背景对比度 **≥ 3:1**，任一主题下不协调即不通过。

## 9. 附录：内容安全要求（P0 强制）

- 全站需有**醒目的安全提示**：量力而行、循序渐进、出现疼痛立即停止、有伤病者先咨询医生。
- 每式页面应可一键跳转至安全提示 / 训练原则。
- 关于页需含**医疗免责声明**：本网站为健身科普与动作指导，非医疗建议；因训练导致的伤害本站不承担责任。
- 涉及高危动作（如单臂倒立撑、铁板桥等高阶式）应有额外风险提示。

### 9.1 安全提示在全站视觉中的呈现要求（**v1.1 新增**）

> 安全提示在**浅色主题下必须醒目**，不得因浅色底 / 低对比而弱化。

| 元素 | 呈现要求 |
|---|---|
| **安全提示条**（首页 / 全站顶部） | 使用 `--danger` 语义色：**浅红底块**（如 `#FEF2F2`）+ `--danger` 文字 / 图标 + 左边框加粗；配警示图标（**图标不只靠颜色，用形状 + 文字双重传达**） |
| **风险提示块**（高危动作页内） | 独立高对比块（`--surface-2` 底 + `--danger` 左边框 + 加粗标题「⚠ 风险提示」），文字对比度 ≥ 4.5:1 |
| **对比度要求** | 提示文字对背景 **≥ 4.5:1**；边框 / 图标等非文字元素 **≥ 3:1**（与 §7.3 一致） |
| **不依赖颜色** | 所有安全提示**同时**用「图标 + 加粗标题 + 明确文案」表达，不能仅靠红色区分（照顾色觉障碍用户） |
| **可点击入口** | 「跳转安全提示 / 训练原则」入口触控目标 **≥ 44×44px** |

### 9.2 示意图与文字一致性（**v1.2 新增 · v1.3 改为条件性条款**）

> **当前状态（v1.3）**：**首版不提供任何图片**，故本节**暂不适用**。
> **但条款保留**——**将来补入图片时，本节自动生效**，无需再次修订 PRD。
